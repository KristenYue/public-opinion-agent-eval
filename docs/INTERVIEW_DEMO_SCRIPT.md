# 3 分钟面试 Demo 讲解稿

在线地址：[ModelScope 舆情研判 Agent](https://modelscope.cn/studios/KristenYue/public-opinion-agent-demo)

## 演示前准备

1. 提前打开在线 Demo，确认页面显示“运行中”。
2. 第一轮保留页面预置的 5 条评论，先稳定讲清三条决策路径。
3. 点击“加载示例”，再点击“运行研判”。
4. 重点展示三条决策路径：`fast_path`、`qwen_reviewed`、`manual_required`。
5. 不把完整流程的 75% 描述成“模型准确率”。
6. 若面试官要求换评论，切换“现场自由测试（严格复核）”，同时补充事件目标和背景。

## 逐字讲解稿

### 0:00–0:25　项目定位

> 这是我把本科情感分析毕设重构成的一个可复核舆情研判 Agent。本科模型在原数据分布内表现不错，但换到新事件、反讽和依赖上下文的短评论时，经常高置信判断错误。因此我没有只追求替换一个更大的分类器，而是把重点放在错误识别、分级路由、人工接管和全链路审计上。

### 0:25–0:50　输入与运行

操作：指向事件背景、研判任务和 5 条预置评论，点击“运行研判”。

> 输入不仅有评论，还有事件背景和研判目标。工作流先用 XGBoost 做低成本快速判断，同时引入辅助模型作为第二信号，再根据模型分歧、主模型低置信和短文本上下文风险，决定每条评论是自动放行、升级复核，还是交给人工。

### 0:50–1:35　三条决策路径

操作：在“人工复核工作台”中依次指出代表性行。

> 第一类是快速路径。例如“这次调整非常合理，给企业带来了新机会”，两个模型方向一致且主模型置信度足够，系统直接进入 `fast_path`，避免所有样本都调用大模型。
>
> 第二类是升级路径。例如“一天一个变化，完全是在折腾普通消费者”，XGBoost 给出 Positive，但辅助模型给出 Negative，系统识别到模型分歧后触发事件感知复核。复核结合事件背景判断为 Negative，并记录升级原因、复核标签、置信度和决策路径。
>
> 第三类是人工兜底。例如“这事跟我没关系”信息量不足，即使模型给出结果，也不应该强行形成业务结论。低置信复核会进入 `manual_required`，页面明确显示“待人工确认”。

### 1:35–2:10　Agent 与可审计性

操作：指向检索证据、风险结论、复核状态和完整审计 JSON。

> 这个项目的 Agent 特征不是开放式自由规划，而是受控自治。LangGraph 保存逐节点状态，运行时信号决定检索证据是否采纳、是否调用复核器、是否允许覆盖基线，以及何时转人工。历史事件检索只提供上下文，不声称证明因果关系。每次工具调用、升级原因、降级状态和最终标签都可以审计。

### 2:10–2:35　人工闭环

操作：在需要人工复核的最后一列选择标签，指出“应用人工复核并重新生成简报”按钮；面试时间充足时再点击。

> 对不确定样本，审核人员只需要修改最后一列并重新生成简报。人工结论会写回状态，复核状态更新为 `human_completed`。这样系统不会把不可靠的自动输出包装成确定答案。

### 2:35–3:00　评测结果与边界

> 我按事件而不是随机评论切分数据，避免同一事件泄漏到训练和测试。锁定阈值后，两个未见测试事件共 80 条样本上，XGBoost 基线 Accuracy 是 42.5%；事件感知纯自动流程提升到 58.75%。系统实际自动处理的 77.5% 样本中，选择性自动 Accuracy 是 67.74%；其余 22.5% 进入人工兜底。完整流程结果是 75%，但这包含人工接管，不能称为模型准确率。Qwen 在测试中修正了 13 个 XGBoost 错误，未产生 harmful override。当前样本规模仍小，所以我的结论是工程可行性证据，而不是生产 SLA。

## 页面异常时的兜底话术

如果在线 Reviewer 没有 API Key：

> 公开 Demo 为了不暴露 API Key，对预置样例使用冻结的离线验收回放，并在页面明确标识；自由输入的争议样本不会伪造 Qwen 结果，而是降级到人工复核。完整的在线 Qwen 调用和盲评脚本保留在仓库中。

如果 ModelScope 临时冷启动：

> 在线空间正在冷启动。我先用项目架构和冻结评测结果说明流程；仓库中保留了相同入口、自动化测试和可复现指标文件。

如果面试官要求随意输入一句话：

> 可以。请同时给出这句话对应的事件目标和背景，因为本项目判断的是评论相对于目标的立场，而不是脱离语境猜情绪。我会切换到现场自由测试模式，所有新评论都强制经过 Reviewer；只有高置信结果才自动写回，否则显示待人工确认。

现场操作：

1. 选择“现场自由测试（严格复核）”；
2. 填写面试官给出的评论，并确认目标和背景完整；
3. 点击“运行研判”；
4. 指出策略版本 `strict_live_test_v1` 和升级原因 `strict_live_test`；
5. 若结果为 `manual_required`，说明可靠性门禁正常拒绝不确定结论。

## 高频追问简答

### 为什么不直接全部使用大模型？

成本、延迟、可用性和误覆盖风险都需要控制。XGBoost 负责明确样本的快速路径，大模型只处理被路由的争议样本，低置信结果继续交给人工。

### 为什么保留准确率不高的 XGBoost？

它在系统中是可解释的基线信号和快速路径，不是最终裁决者。项目价值之一就是识别旧模型在分布外数据上的失效，并通过路由限制错误外溢。

### 这是 Agent 还是普通流水线？

它是边界受控的 Agent 工作流：运行时状态和工具结果会改变后续路径，系统可以选择放行、检索、复核、覆盖或人工接管；同时所有工具和覆盖规则预先受控，适合高风险研判场景。

### 75% 是不是模型准确率？

不是。纯自动全量 Accuracy 是 58.75%；75% 包含 22.5% 的人工兜底，属于完整流程结果。

### 下一步如何继续提高？

优先扩大独立标注的新事件测试集，按错误类型补充困难样本，校准 Reviewer 置信度，并持续监控自动覆盖率、负面召回率、人工介入率和 harmful override，而不是只优化单一 Accuracy。
