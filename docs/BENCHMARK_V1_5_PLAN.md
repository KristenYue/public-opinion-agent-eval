# Benchmark v1.5：跨事件可靠性扩展协议

## 目标

在不改写 v1 历史结果的前提下，把当前 7 个事件、275 条上下文标注扩展到约 12 个事件、575–625 条。v1.5 优先增加事件和错误模式的多样性，用于检验事件感知路由、Qwen 复核与人工兜底是否能在未见话题上保持稳定，而不是把一万条弱标签包装成“高质量数据集”。

v1 的冻结报告和 0.80 阈值保持不变。v1.5 使用新的版本号、清单、代码提交和结果文件，不覆盖 `event_aware_protocol_final_metrics.json`。

## 新增规模与分工

| 槽位 | 数量 | 每事件最终标注 | 用途 |
|---|---:|---:|---|
| pilot / development | 1 个事件 | 60–70 条 | 验证字段、标注规范和错误分类；允许在冻结前修流程 |
| frozen external test | 4 个事件 | 各 60–70 条 | 只用于最终一次评测；不调阈值、不改提示词 |
| 合计新增 | 5 个事件 | 300–350 条 | 总标注量达到约 575–625 条 |

现有 2 个冻结测试事件继续保留。v1.5 最终测试将覆盖约 6 个事件、320–360 条评论，比单纯增加同事件评论更能暴露跨事件方差。

## 五类事件槽位

新增事件不能只追求热度，必须分别覆盖不同失效模式：

1. **反讽与隐性否定密集**：表面正向词与真实立场相反。
2. **辟谣、求证与不可评分**：包含转述、问句、纯话题标签、无关内容。
3. **短文本与指代依赖**：如“又来了”“就这？”“终于处理了”，必须结合原帖判断。
4. **正向事件中的事实/负面混合**：防止模型把事件整体正向误当成每条评论都正向。
5. **政策或平台治理争议**：同一措施下同时存在支持、观望、质疑和利益相关方立场。

事件之间要有明显领域差异，避免五个事件都属于娱乐或消费投诉。

## 每个事件的采集和筛选

1. 先采集 120–180 条候选评论，并保存事件目标、原帖背景、来源时间和匿名化来源标识。
2. 全局去重后筛出 60–70 条，不按模型预测抽样，不为了凑负面比例复制或改写文本。
3. 尽量让 Negative、Neutral、Positive、Unscorable 都有样本；若真实事件缺少某一类，保留真实分布并在清单中说明，不人工伪造平衡。
4. 同一原帖最多贡献最终样本的 25%，避免结果被单一上下文主导。
5. 删除纯广告、泄露个人信息、无法恢复上下文的残片；原始微博语料只留本地，不提交公开仓库。

## 标注字段

每条最终样本必须包含：

- `sample_id`
- `event_id`
- `split`
- `target`
- `context`
- `content`
- `human_label`
- `human_confidence`
- `needs_review`
- `review_note`
- `review_round`

标签仍使用 `Negative / Neutral / Positive / Exclude`；评测时把 `Exclude` 归一化为 `Unscorable`。标注判断的是“评论相对于事件目标的立场”，不是脱离语境的通用情绪。

## 冻结门禁

按以下顺序执行，任何一步失败都不发布 v1.5 指标：

1. 完成 pilot 标注，修正字段、说明和评测代码。
2. 选定 4 个新测试事件，生成带哈希的事件清单。
3. 在查看测试标签前记录代码 commit、阈值 `0.80`、Qwen 模型名、提示词版本和随机种子。
4. 测试事件只做盲标；模型输出与人工标签分开保存。
5. 对低置信、歧义和抽样复核项做第二轮自我复核；没有独立第二标注者时，只报告“复核率、标签修正率”，不报告 Kappa。
6. 运行一次 v1.5 冻结评测并生成独立结果文件；不因结果难看回头改标签或提示词。

## v1.5 必须报告的结果

- 总事件数、各 split 事件数和样本数
- 每类标签分布、每事件分布
- XGBoost、纯自动级联、选择性自动、完整流程四种口径
- Accuracy、Macro-F1、Negative Recall、自动覆盖率、人工介入率
- Qwen 纠错数与 harmful override 数
- 每事件指标及事件间最小值/最大值
- 评论级 bootstrap 95% CI，并明确其不能代表未见事件总体
- 自我复核数量、标签修正数量和修正率
