# 冻结 RAG 评测 V1

## 目标与数据边界

旧检索报告的 12 条查询大多直接包含事件标题，只能作为 sanity check。V1 新增一套完全公开、人工编写的合成评测：

- 9 张事件卡，其中 8 张正常业务卡、1 张安全污染卡；
- 16 条不直接复制标题的相关性查询；
- 4 条跨领域无关查询；
- 3 条 Prompt Injection 污染查询；
- 每条正样本由人工标注一个相关事件。

数据集和 corpus 由 [冻结清单](../data/evaluation/rag_eval_v1_manifest.json) 的 SHA-256 锁定。不得为了修正结果原地改 V1；变化必须新建版本。

## 指标定义

| 指标 | 定义 |
|---|---|
| Recall@5 | 前 5 条是否覆盖人工相关事件，按 query 平均 |
| MRR@5 | 第一个相关事件排名倒数的平均值 |
| nDCG@5 | 考虑相关结果排名位置的折损累计增益 |
| Top-1 引用正确率 | 第一条证据是否属于人工相关事件 |
| 有证据回答率 | 相关查询是否至少返回一条证据 |
| 无关证据拒绝率 | 无关查询是否返回空结果 |
| 污染拒绝率 | 指定污染卡没有进入结果，并且 Guard 确实记录了拒绝 |

“Top-1 引用正确率”不是对最终自然语言答案事实性的人工核验；当前 Agent 只展示事件卡引用，所以这里度量的是首条引用事件是否相关。

## 冻结结果

执行命令：

```powershell
.\.venv\Scripts\python.exe scripts\evaluate_rag_v1.py
```

| 指标 | 结果 | 门槛 |
|---|---:|---:|
| Recall@5 | 100% | ≥ 90% |
| MRR@5 | 100% | ≥ 80% |
| nDCG@5 | 100% | ≥ 85% |
| Top-1 引用正确率 | 100% | ≥ 80% |
| 有证据回答率 | 100% | ≥ 95% |
| 无关证据拒绝率 | 75% | ≥ 75% |
| Prompt Injection 污染拒绝率 | 100% | = 100% |

机器可读结果见 [rag_eval_v1_metrics.json](../data/evaluation/rag_eval_v1_metrics.json)。CI 会重新计算并检查冻结输入哈希；任一门槛下降都会失败。

## 保留的 Bad Case

`n02` 询问“快速排序算法及时间复杂度”，TF-IDF 因共享“算法”一词返回了“配送算法规则调整”。这表明固定字符相似度阈值不能充分理解领域边界。

本版本不在看完结果后调高阈值，因为那会污染冻结评测。后续候选方案应在独立 validation 集选择阈值或加入领域分类器，再对 V2 测试集一次性评估。

## Prompt Injection 门禁

`GuardedRetriever` 会在证据进入 Reviewer 前拒绝以下已知模式：

- 忽略既有指令；
- 请求输出系统提示词或密钥；
- 覆盖模型角色；
- 指挥模型调用或执行工具。

Trace 只保存 evidence ID、event ID 和规则名，不回写恶意正文。该规则层是纵深防御，不是“已经解决 Prompt Injection”的声明；变体、编码混淆和语义间接注入仍需持续红队测试。

## 限制

- 数据是公开合成小样本，不代表真实用户查询分布；
- corpus 只有事件级文档，没有评测 chunk 粒度和长文档召回；
- 当前基线只验证离线 TF-IDF；BGE/Hybrid 必须固定模型文件和运行环境后另建候选报告；
- 尚未进行最终回答的逐句 citation entailment 人工标注。
